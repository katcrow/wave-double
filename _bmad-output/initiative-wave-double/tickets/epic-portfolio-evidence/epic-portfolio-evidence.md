# 전략 M의 자금 제약을 반영한 포트폴리오 위험을 측정한다

## Description

부모의 R10, R11, R12를 아래 세 작업으로 검증하거나 보완한다. 이미 구현된 기능은 다시 개발하지 않으며 검증 정의의 존재와 운영 성공 증거를 구분한다.

## Outcome

전략 M의 자금 제약을 반영한 포트폴리오 위험을 측정한다. 통과·실패·미확인 결과와 근거를 구분할 수 있다.

## Requirements

- R1 (parent R10): 포트폴리오의 가용 현금 초과 진입을 차단한다. 완료 증거: 초기자본 100·종목비중 25%·동일일 5종목·청산 전 사례에서 다섯째 진입을 거부하고 현금이 음수가 되지 않는다. 날짜 불일치·중복종목·청산일 진입 정책도 명시·검증한다.
- R2 (parent R11): M 전용 청산 거래를 계좌 평가에 연결한다. 완료 증거: M 원본 거래의 진입·청산·비용을 보존하고 합성 계좌가 수작업 계산과 일치한다. WAVE_BACKTEST_RESULTS_DIR 지정 시 커밋 baseline은 바뀌지 않는다.
- R3 (parent R12): 전체 유니버스에서 M의 자본곡선과 MDD를 측정한다. 완료 증거: 데이터/기간/파라미터/비용/자금조건/명령/산출물로 재실행 가능하며 중복보유·현금음수·한도위반 없이 MDD를 산출한다. 운영 채택 결정은 별도다.

## Constraints

부모의 Constraints를 모두 따른다. 검증 spike에서 문제를 발견하면 재현 조건·영향·후속 수정 범위를 기록하며 오류를 통과로 숨기지 않는다. 운영 규칙 변경이 필요하면 결정 항목으로 분리한다.

## Done when

- 초기자본 100·종목비중 25%·동일일 5종목·청산 전 사례에서 다섯째 진입을 거부하고 현금이 음수가 되지 않는다. 날짜 불일치·중복종목·청산일 진입 정책도 명시·검증한다.
- M 원본 거래의 진입·청산·비용을 보존하고 합성 계좌가 수작업 계산과 일치한다. WAVE_BACKTEST_RESULTS_DIR 지정 시 커밋 baseline은 바뀌지 않는다.
- 데이터/기간/파라미터/비용/자금조건/명령/산출물로 재실행 가능하며 중복보유·현금음수·한도위반 없이 MDD를 산출한다. 운영 채택 결정은 별도다.
- 운영에 닿는 결과는 동일 배포 기준의 실측 증거로 수용한다. 수정이 있으면 관련 회귀와 배포 후 확인까지 포함하며 로컬 통과만으로 운영 완료라 하지 않는다.

## Boundaries

- 계좌 회계·M 거래 연결·위험 측정을 소유한다. 운영 전략 파라미터 변경·새 전략 채택·자동 주문은 제외한다.
- 검증 결과 보고와 제품 릴리스 완료는 별개이며 미해결 운영 오류가 있으면 에픽 수용 상태에 명시한다.
- 첫 검증의 환경·증거 기록은 이 에픽이 소유하고 외부 전제는 tickets.toml의 after로 연결한다.
