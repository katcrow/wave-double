# Product Brief: wave-double — 매수후보 추천 대시보드

## Executive Summary

개인 투자자 Neo가 직접 백테스트로 검증해 확정한 **3가지 매수 전략(A·B·C)** 을, 매일 **조건검색식이 뽑은 후보 모집단**에 적용해 **당일 종가 기준 매수 후보**를 자동으로 추천하는 **1인용 실전운영 도구**입니다. 후보 중 전략 태깅(A/B/C)이 붙은 종목만 노출되며, 각 종목은 2일전/1일전/당일 3줄의 가격·거래량·등락율·수급(외인/기관/개인/프로그램) 데이터와 함께 보여집니다.

**본 브리프는 목업/파일럿 없이 곧바로 실전운영으로 개발**하며, **V1 범위는 매수 추천에 한정**합니다. 실제 매매(주문·체결)는 사용자 Neo가 수동으로 진행하고, 도구는 추천 근거(전략 태깅·수급)와 사후 성과 추적만 제공합니다. 실전 성과가 검증되면(`candidate_outcome` 누적으로 백테스트 기대치 수준 확인) 그때 **자동매매 시스템을 별도 프로젝트로 개발**하는 후속 단계로 연결됩니다.

운영은 **전액 무료** 원칙 아래 프론트엔드 Next.js + 로직 파이썬(GitHub Actions 스케줄러) + DB Supabase 무료 플랜으로 구성됩니다. 장중 **30분 간격 배치**로 흐름을 파악하고 시장 전체 수급 흐름까지 함께 보여줍니다. 핵심 가치는 "검증된 승률(68%대)을 실전 종목 발굴로 자동화"하는 데 있습니다.

## The Problem

- 백테스트로 우수한 전략(A: 68.7%, B: 68.9%, C: 66.0% 승률)을 발굴했지만, 이를 **매일 종목 발굴**로 옮기는 과정이 수동·비체계적입니다. `screen_abc.py`를 직접 돌리고 CSV를 열어보는 식이라, 조건검색식 후보(모집단)와 실제 전략 시그널이 맞닿는 순간을 놓치기 쉽습니다.
- 수급 데이터(외인/기관/개인/프로그램)가 분산되어 있어, 후보 종목의 "수급 흐름"을 한눈에 보기 어렵습니다. 종목별 3일치 + 시장 전체 수급을 종합해 판단하려면 많은 API를 일일이 호출해야 합니다.
- **검증 공백**: 백테스트 68%대 승률은 104종목 전체 대상입니다. 실전에서는 조건검색식이 뽑은 **후보 모집단 한정**으로 시그널을 계산하므로 모집단 편향으로 인해 실전 승률이 달라질 수 있습니다. 목업 없이 실전운영을 시작하는 만큼, 이 편향을 **관찰 가능한 경계 지표로** 만들고 사후 결과를 적재해 백테스트 기대치와 대조하는 검증 루프가 필요합니다.

## The Solution

매일 (그리고 장중 30분 간격으로) 자동 실행되는 파이프라인이:

1. LS OpenAPI **조건검색식**(t1859)으로 후보 모집단을 갱신합니다.
2. 후보들에 대해 **전략 A/B/C 시그널**을 계산해 태깅하고, 태깅된 종목만 후보 목록으로 확정합니다.
3. 각 후보 종목의 **2일전/1일전/당일** 3줄 데이터(종가·거래량·등락율·외인/기관/개인/프로그램 순매수)와 **시장 전체 수급** 화면을 제공합니다.
4. **당일 종가** 기준 추천을 백테스트 룰(TP+3%/SL-3%)에 맞춰 제시합니다.

GitHub Actions 스케줄러가 기본으로 자동 실행하며, **프론트엔드에서도 시간과 무관하게 수동으로 트리거**할 수 있어 반자동 유연성을 제공합니다.

**장중 30분 배치의 역할**: 최종 추천은 당일 종가 기준이므로 장중 배치는 추천 자체를 확정하지 않습니다. 대신 (가) 오전 후보가 유지되는지(시그널 소멸/유지 모니터링), (나) 실시간으로 갱신되는 수급 흐름을 Neo가 장중에 참고해 매수 여부·타이밍을 사전 판단할 수 있는 **경보·참고 지표**로 동작합니다.

**실전 검증 루프(V1 핵심)**: 목업 없이 실전운영이므로, 대시보드가 추천(태깅)한 모든 후보의 **사후 결과(TP +3% 도달 여부 / SL -3% 도달 여부 / 진행중 여부)를 후보별로 자동 적재·추적**합니다. 이렇게 쌓인 실전 데이터를 백테스트 기대치(승률 ~68%, PF ~2.0)와 대조해, 전략·후보 모집단 편향이 실전에서 실제로 어떻게 나타나는지 측정합니다.

## What Makes This Different

- **검증된 엣지**: 단순 지표 나열이 아니라, 본인이 73개월 데이터로 최적화·검증한 확정 전략 3종(승률 66~69%, PF 1.8~2.1)을 그대로 실전 적용.
- **무료·무인 운영**: 유료 서비스 의존 없이 Next.js + GitHub Actions + Supabase 무료 플랜만으로 상시 자동화.
- **후보 vs. 전략의 연결**: 조건검색식(모집단)과 전략 태깅(A/B/C)을 명확히 이어서, "왜 이 종목이 노출됐는지"를 다중 태그로 설명.

## Who This Serves

- **단일 사용자: Neo(본인)** — 개인 투자자. 1인용 실전운영 도구로, 외부 사용자를 타겟하지 않습니다. 성공 기준은 매일 아침 대시보드 하나로 "오늘 후보는 누구, 어떤 전략으로, 수급은 어떤지"를 5분 안에 확인하고 판단할 수 있는 것.
- 검증 대상은 사람이 아닌 **데이터 루프**입니다. 실전 추천 후보의 사후 TP/SL 결과가 쌓여 백테스트 기대치와 얼마나 일치하는지가 곧 이 도구의 가치 검증 수단입니다.

## Success Criteria

- 매 거래일 자동 배치(조건검색 + 전략 태깅 + 수급)가 실패 없이 완료되는 안정성.
- 장중 30분 간격 배치가 정상 동작하며, 수동 트리거도 프론트엔드에서 가능.
- 후보 종목의 3일치 가격·수급 데이터와 시장 전체 수급이 대시보드에서 정확히 표시.
- **모든 추천(태깅) 후보의 사후 TP/SL 도달 결과가 자동 적재·추적**되며, 실전 승률·PF를 백테스트 기대치(승률 ~68%, PF ~2.0)와 대조할 수 있음.
- 실전 추천 품질이 백테스트 기대 수준을 유지하는지 관찰: **후보 모집단 한정 시그널로 인한 승률 편향**을 경계 지표로 보고, 크게 이탈하면 원인(조건검색식 범위, 시그널 재계산 로직)을 점검.

## Scope (V1)

**포함**
- 조건검색식 후보 수집(t1859), 전략 A/B/C 시그널 태깅, 태깅된 후보만 노출
- 후보별 2일전/1일전/당일 3줄 데이터(종가/거래량/등락율/외인·기관·개인·프로그램)
- 시장 전체 수급 화면
- GitHub Actions 스케줄 자동 실행 + 프론트엔드 수동 트리거
- Next.js 대시보드, Python 로직, Supabase 저장
- **수급 판단 참고 룰**: 대시보드가 수급 데이터를 단순 노출만 하지 않고, Neo가 정의한 기준(예: 외인/기관 순매수 강도)에 따라 후보에 판단 힌트를 함께 표시
- **사후 결과 적재·추적**: 태깅된 후보별 TP(+3%)/SL(-3%)/진행중 상태를 자동 기록 → 실전 승률·PF를 백테스트 기대치와 대조하는 검증 화면

**제외(V1 이후)**
- 실제 주문·체결 자동화(매매 실행) — **자동매매는 V1 사후 성과가 검증된 후 별도 시스템으로 개발**
- 실시간(초 단위) 스트리밍 시세 — 장중 배치는 30분 간격 일괄
- 금융/투자자문 성격의 조언 기능

## Vision

성공 시, 검증된 전략이 매일 자동으로 후보를 발굴하고 수급 맥락까지 함께 제공하는 **개인 트레이딩 보조 허브**가 됩니다. 이후 실제 매수·청산 트래킹(TP/SL 관리), 전략 성과 리포팅, 더 많은 조건검색식 확장으로 발전할 수 있습니다. V1의 사후 결과 적재는 이 방향의 기초 데이터로 재사용됩니다.

**검증된 후속 로드맵 (V1 이후)**
1. **V1**: 매수 추천만 자동화 + 사후 성과 추적(수동 매매) — 본 브리프의 범위.
2. **성과 검증 게이트**: `candidate_outcome`으로 실전 승률·PF가 백테스트 기대치 수준임을 일정 기간 확인하면 자동매매로 진행 판단.
3. **자동매매(V2, 별도 프로젝트)**: 성과 검증 통과 후 주문·체결 자동화를 독립 시스템으로 설계·개발.

## Open Questions

- 전략 A/B/C 시그널은 **후보 모집단 한정**으로 계산한다고 가정(백테스트의 104종목 전체 대상과는 다른 좁은 범위). **이미 V1에 실전 후보 사후 결과 적재를 포함**하므로, 이 편향이 실제로 승률을 어떻게 바꾸는지 실전 데이터로 검증함.
- 외인/기관/프로그램 종목별 일별 데이터의 "당일" 갱신 시점(장 마감 후 일괄 반영 여부).
- 수급 판단 힌트에 쓸 **기준(임계값) 확정** — 대시보드에 넣을 "좋은 수급"의 정의(외인/기관 순매수 강도, 프로그램 방향 등)를 Neo와 확정.
- 실전 사후 결과의 **청산 시점 정의** — 미청산(진행중) 종목 처리, TP/SL 도달의 관측 방식(장 마감 종가 기준 vs 장중 최고/최저).
