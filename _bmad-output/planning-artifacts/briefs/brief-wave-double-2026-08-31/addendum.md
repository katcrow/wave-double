  → `python -m backtest.indicator_opt.stoch_db --k-period 14 --threshold 20 --weekly --wk-period 20 --wd-period 3`
- 전략 C: 스토캐스틱 3바닥 하락 다이버전스 (K5·D3·div20·gap5)
  → `python -m backtest.indicator_opt.run --indicator div_stoch3`
- 스크리닝 진입점: `python -m backtest.indicator_opt.screen_abc`
- ⚠️ 기존 스크리너는 104종목 전체 대상. "후보 모집단 한정" 재계산 로직 별도 구축 필요.

## 2. 아키텍처 스케치 (무료 운영 제약 내)

```
[GitHub Actions 스케줄러, Python]
   ├─ 조건검색(t1859) → 후보 모집단 갱신
   ├─ 전략 A/B/C 시그널 계산 (후보 모집단에 태깅)
   ├─ 후보별 수급(t1702/t1636/t1601) 3일치 수집
   ├─ 시장 전체 수급(t1601/t1631) 수집
   ├─ 사후 결과 추적 (candidate_outcome): 진입가 대비 고가/저가로 TP/SL 도달 판정
   └─ Supabase로 적재
        ▲
[Next.js 대시보드] ──(RPC/화면)── Supabase
   ├─ 후보/수급 조회 + 수급 판단 힌트 표시
   ├─ 실전 승률·PF vs 백테스트 기대치 대조(검증 화면)
   └─ 수동 GitHub Actions 트리거 (시간 무관)
```

- **스케줄**: 장중 30분 간격 배치 + 시장 개장 전/후 일괄 갱신
- **수동 트리거**: GitHub Actions `workflow_dispatch` → 프론트엔드 버튼으로 REST 호출(PAT 또는 앱 토큰)
- **무료 플랜 제약 관심 포인트**
  - GitHub Actions 표준 플랜 월 **2,000분**. 30분×12회/일×20거래일 ≈ 240회+α → 회당 1~3분이면 여유. 시장전체+종목별 다건 호출 시 러닝타임 관리 필수.
  - Supabase 무료: DB 용량·실시간 등 한도 확인 필요 (일별 스냅샷 저장 방식 권장, 무한 누적 지양)
  - LS OpenAPI TR별 초당 제한(대부분 개인 1~2건/초) → 배치 내 직렬/스로틀 호출 필요

## 3. 대시보드 데이터 모델 (제안)

- `candidates` — 종목코드, 종목명, 조건검색일자, 태깅된 전략id[] 
- `candidate_tags`(연결) — candidate ↔ strategy(A/B/C), 시그널일, 파라미터 메타
- `supply_3day` — candidate + 날짜(2일전/1일전/당일) + 종가/거래량/등락율 + 외인/기관/개인/프로그램 순매수
- `market_supply` — 시장(코스피/코스닥) + 날짜 + 수급 집계
- `runs` — 배치 실행 이력(성공/실패, 트리거 유형: 스케줄/수동) → 안정성 추적
- `candidate_outcome` — **사후 결과 추적(V1 필수)** candidate + 진입일(태깅 시그널일) + 진입가 + 이후 일자별 고가/저가/종가 → TP(+3%) 도달 여부 / SL(-3%) 도달 여부 / 진행중, 도달일 저장. 실전 승률·PF를 백테스트 기대치와 대조하는 원천.

## 4. 성공지표 산정 참고

- 백테스트 승률: A 68.7% / B 68.9% / C 66.0% (TP3%/SL3%, 104종목 73개월)
- PF: A 2.05 / B 2.08 / C 1.82
- "노출된 후보의 TP/SL 도달률" 실전 추적 지표를 백테스트 기대치와 대조
- ⚠️ **모집단 편향 경계**: 실전 승률은 "조건검색식 후보 한정" 대상이므로 104종목 전체 백테스트와 직접 비교 불가. `candidate_outcome`에서 수집한 실전 승률·PF를 기준으로 잡되, 이탈 시 조건검색식 범위·시그널 재계산 로직을 점검.
- **청산 관측 방식**: 백테스트는 시그널 봉 종가 진입 → 고가/저가로 TP+3%/SL-3% 판정. 실전도 동일 룰을 따라 진입가 대비 이후 일자별 고가/저가로 TP/SL 도달을 판정해 비교 가능성을 유지(Open Question 참조).
