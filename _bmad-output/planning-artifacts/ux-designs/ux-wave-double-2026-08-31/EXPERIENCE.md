# wave-double — Experience Spine

`DESIGN.md`가 시각적 정체성의 기준이며, 이 문서는 정보 구조·행동·상태·접근성을 정의한다. 두 문서는 목업이나 구현 세부보다 우선한다.

## Foundation

반응형 웹 대시보드이며 데스크톱/노트북을 주 사용 표면으로 한다. V1은 외부 사용자·인증·모바일 앱을 대상으로 하지 않는 Neo 1인용 운영 도구다. Next.js 기반 UI 시스템을 사용하며, 시각 토큰은 `DESIGN.md`를 따른다. 장중 배치는 최종 추천이 아니라 참고·경보이고, 종가 확정 배치에서만 당일 추천 상태를 확정한다.

핵심 UX 원칙은 세 가지다.

1. **판단까지 5분** — 후보가 누구인지와 왜 노출됐는지를 첫 화면에서 확인한다.
2. **데이터 신뢰도 우선** — 모든 핵심 숫자에 최신 시각·배치 상태·원천을 연결한다.
3. **검증을 숨기지 않음** — 표본 부족, 모집단 편향, TIMEOUT, 수급 미확정을 불편하더라도 먼저 보여준다.

## Information Architecture

| Surface | Route / 진입 | 목적 |
|---|---|---|
| 오늘의 후보 | `/` 앱 진입 | 당일 태깅 후보, 전략 근거, 수급 힌트, 시장 흐름 확인 |
| 후보 근거 패널 | 오늘의 후보 카드 확장 | 후보별 3일치 가격·거래량·수급 원천 확인 |
| 성과 검증 | `/tracking` 내비게이션 | outcome, 실전 승률·PF, 백테스트 대조, 모집단 편향 확인 |
| 배치 이력 | `/runs` 내비게이션 또는 신뢰도 바 상세 | 자동·수동 배치와 단계별 성공/실패 확인 |

메인 대시보드와 추천후보군 추적페이지는 반드시 별도 라우트다. 1단계 모달 위에 또 다른 모달을 쌓지 않는다. 후보 카드의 확장은 같은 페이지의 disclosure이며, 추적 페이지의 필터는 페이지 상태로 유지한다.

## Voice and Tone

짧고 관찰 가능한 문장을 쓴다. 금융 조언이나 확정적 표현을 쓰지 않는다.

| 상황 | 사용 | 피하기 |
|---|---|---|
| 추천 제목 | `오늘의 후보` | `오늘 반드시 사야 할 종목` |
| 전략 근거 | `전략 D · 전략 E 시그널`(매칭된 전략만, A/B/C/D/E/F 가변 개수) | `강력 매수 신호` |
| 좋은 수급 | `좋은 수급` | `매수 확정` |
| 미확정 | `판정 불가 · 장 마감 후 확정` | `수급 0` |
| 실패 | `배치 실패 · 마지막 성공 08:10` | `후보 없음` |
| 표본 부족 | `표본 부족 · 종결 8/30건` | `승률 50%` |
| 지연 | `데이터가 60분 이상 오래됨` | `실시간` |

## Component Patterns

| Component | Behavioral rules |
|---|---|
| Data trust bar | 항상 화면 상단에 고정한다. 실패/부분성공/미갱신은 후보 목록보다 먼저 읽힌다. 수동 실행은 중복 클릭을 막고 실행 중 상태를 보여준다. |
| Candidate card | 기본은 요약 1행이다. 클릭/Enter로 하나만 펼칠 수 있으며, 다른 카드를 열어도 사용자가 보고 있던 카드가 갑자기 닫히지 않는다. |
| Strategy tag | 하나 이상의 태그를 모두 표시한다. 태그 클릭은 필터가 아니라 해당 전략 설명/성과로 이동하는 보조 액션이다. |
| Supply hint | `좋은 수급`/`미충족`/`판정 불가` 3상태를 유지한다. 장중에는 종목별 수급이 없으므로 `판정 불가`가 기본값이다. |
| Evidence panel | 거래일 순서는 최신이 위다. 결측은 `미수집`으로 표시하고 빈 칸/0과 구분한다. 원천이 폴백이면 `t1852`/`t1856` 등 원천을 표시한다. |
| Market supply | 코스피/코스닥 탭 전환은 URL 또는 로컬 상태에 보존한다. 시장 전체는 장중에도 갱신될 수 있으므로 종목 수급과 다른 신선도 라벨을 사용한다. |
| Metric comparison | 태깅된 전략(A/B/C/D/E/F, 가변 개수) 및 전체를 전환할 수 있다. 종결 30건 미만이면 승률·PF 대신 표본 게이트를 표시하고 기대치와의 판정을 실행하지 않는다. (2026-09-04 Correct Course: D/E 추가, 2026-09-07 Correct Course: F 추가) |
| Outcome row | TP/SL/TIMEOUT/OPEN과 예외 SUSPENDED/DELISTED를 구분한다. OPEN은 항상 별도 카운트로 표시하며 성과 분모에 포함하지 않는다. |
| Bias diagnostic | 날짜를 선택하면 후보 모집단∩전략 시그널, 백테스트 유니버스 시그널, 기회 누락을 함께 설명한다. 차이를 실패 원인으로 단정하지 않는다. |

## State Patterns

| State | Treatment |
|---|---|
| 정상 종가 확정 | `종가 확정 · 16:00 KST`와 후보별 수급 힌트를 표시한다. |
| 장중 참고 | `장중 참고 · 최종 추천 미확정`을 고정 표시하고 종목별 당일 수급은 `미확정`으로 둔다. |
| 로딩 | 실제 카드와 같은 높이의 3~6개 skeleton을 표시한다. 페이지 전체를 빈 검정 화면으로 만들지 않는다. |
| 후보 없음 | `오늘 태깅된 후보가 없습니다.`와 `조건검색 결과/전략 시그널 기준`을 설명한다. 배치 실패가 있으면 빈 상태보다 실패 상태를 우선한다. |
| 부분성공 | 수집된 후보는 표시하되 `N종목 수급 미수집`, 미수집 목록, 재실행 액션을 함께 제공한다. |
| 실패 | 마지막 정상 데이터는 삭제하지 않고 stale로 표시한다. 상단에 실패 시각·단계·수동 실행을 제공한다. |
| 휴장일 | 실패가 아닌 `휴장일 · 배치 스킵`으로 표시한다. 최신 거래일 보기 링크를 제공한다. |
| stale | 현재 시각 기준 60분 이상이면 배치 시각과 `오래됨`을 함께 표시한다. 자동으로 최신처럼 보이게 하지 않는다. |
| 폴백 원천 | 메인 신뢰도 바와 후보 근거에 원천을 드러내며, 추적 페이지에서는 원천별 필터를 제공한다. |
| 표본 부족 | `종결 n건 / 진행중 m건`을 유지하되 승률·PF 숫자는 숨긴다. n/30 진행률만 보여준다. |
| 가격 보정 이상 | SUSPENDED로 중단하고 자동 TP/SL 판정을 하지 않는다. 원인과 확인 필요성을 안내한다. |

## Interaction Primitives

- 키보드: `j/k`로 후보 이동, `Enter`로 근거 패널 열기/닫기, `/`로 후보 검색, `r`로 데이터 새로고침, `g t`로 오늘의 후보, `g v`로 성과 검증, `Esc`로 패널·팝오버 닫기.
- 마우스: 카드 어디를 눌러도 상세가 열리되, 전략 태그·외부 링크·수동 실행 버튼은 독립 액션으로 동작한다.
- 포인터가 없는 환경: 후보 카드의 hover 액션을 제공하지 않는다. 모든 액션은 항상 DOM에 존재하거나 포커스로 드러난다.
- 새로고침: 자동 폴링은 장중 30분 배치 주기와 혼동되지 않게 하지 않는다. 사용자가 수동 새로고침하면 마지막 배치 시각과 데이터 상태를 다시 확인한다.
- 필터: 전략, 수급 힌트, 시그널 상태, 원천으로 필터링한다. 필터 결과가 0건이면 적용된 필터를 보여주고 한 번에 초기화한다.
- 금지: 자동 주문·청산, 매수 확정 카피, 무한 스크롤, 드래그 정렬, 보상 애니메이션, 실시간처럼 보이는 초 단위 갱신.

## Accessibility Floor

- WCAG 2.2 AA를 목표로 하며 텍스트와 상태는 색상만으로 구분하지 않는다.
- 모든 카드와 disclosure는 키보드로 접근 가능하고 열림 상태를 `aria-expanded`로 전달한다.
- 후보 카드에는 종목명·코드·전략 태그·수급 힌트·시그널 상태가 하나의 접근 가능한 이름으로 읽힌다.
- 데이터 테이블은 행/열 헤더를 제공하고 숫자 단위와 기준일을 숨기지 않는다.
- 배치 상태 변경, 새로고침 완료, 오류는 `aria-live="polite"` 영역으로 알린다. 오류가 발생해도 키보드 포커스를 강제로 이동하지 않는다.
- 포커스 링은 `{colors.accent-strong}`과 배경 대비가 충분해야 하며, 마우스 hover보다 먼저 보장한다.
- 브라우저 확대 200%와 Pretendard fallback에서도 카드 내용이 잘리지 않아야 한다. 좁은 폭에서는 3일치 테이블이 날짜별 행 카드로 바뀐다.
- 모션 감소 설정에서는 카드 확장과 토스트 전환을 즉시 처리한다. 숫자 카운트업과 펄스 효과를 사용하지 않는다.

## Responsive & Platform

| 폭 | 동작 |
|---|---|
| `≥ 1200px` | 사이드바 240px, 후보 요약은 2분할, 시장 수급은 후보 목록 아래 전체 폭 |
| `768–1199px` | 사이드바 축소 또는 토글, 후보 요약은 1열 흐름 안의 짧은 2단 구조 |
| `< 768px` | 사이드바는 sheet, 후보 카드는 세로 요약, 3일치 데이터는 날짜별 행 카드, 표본/상태 고지를 상단 고정 |

모바일은 MVP의 주 표면이 아니지만 읽기와 단순 필터는 가능해야 한다. 복잡한 성과 비교는 세로 스택으로 바꾸며, 데이터 열을 억지로 축소해 한 줄에 우겨 넣지 않는다.

## Key Flows

### Flow 1 — Neo가 아침에 오늘 후보를 5분 안에 확인한다

1. Neo가 브라우저에서 `/`를 연다.
2. 상단 신뢰도 바에서 `종가 확정`, 마지막 성공 시각, 자동 배치 여부를 확인한다.
3. 오늘의 후보 카드에서 종목명·전략 태그(A/B/C/D/E/F 중 매칭된 것)·수급 힌트를 훑는다.
4. 관심 후보 하나를 Enter로 열어 3일치 가격·수급 근거와 원천을 확인한다.
5. **Climax:** Neo는 `이 종목 · 전략 D · 좋은 수급`(매칭된 전략만, A/B/C/D/E/F 가변 개수)이라는 근거 묶음을 5분 안에 확인하고 수동 매수 여부를 판단한다.

실패 시: 배치 실패/부분성공이면 빈 목록으로 넘어가지 않고 마지막 성공 시각, 실패 단계, 미처리 건수, 수동 실행 버튼을 먼저 보여준다.

### Flow 2 — Neo가 장중에 후보 유지와 시장 흐름을 참고한다

1. Neo가 `/`에 들어와 `장중 참고 · 최종 추천 미확정`을 확인한다.
2. 시장 전체 수급에서 코스피/코스닥의 외인·기관·개인·프로그램 흐름을 본다.
3. 후보 카드에서 가격·거래량·등락률과 시그널 `유지`/`소멸`을 확인한다.
4. 후보별 수급 힌트가 `판정 불가 · 장 마감 후 확정`임을 확인한다.
5. **Climax:** Neo는 시장 흐름과 시그널 유지 여부를 참고해 종가 전 관찰 우선순위를 정한다. 시스템은 매수 확정처럼 말하지 않는다.

### Flow 3 — Neo가 실전 성과와 백테스트 기대치를 검증한다

1. Neo가 `/tracking`으로 이동한다.
2. 전체 또는 전략 A/B/C/D/E/F 중 하나, 필요하면 후보 원천을 선택한다.
3. 후보별 TP/SL/TIMEOUT/OPEN과 `종결 n건 / 진행중 m건`을 확인한다.
4. 종결 건수가 30건 미만이면 표본 부족 게이트와 진행률을 본다.
5. 30건 이상이면 승률·PF, 95% 신뢰구간, 백테스트 기대치의 구간 내/외 판정을 본다.
6. **Climax:** 이탈이 보이면 Neo는 같은 화면의 모집단 편향 진단에서 기회 누락과 교집합을 확인해 표본 부족·모집단 편향·시그널 재계산 중 어디를 먼저 조사할지 정한다.

## Open Questions & Handoff Notes

- 수급 힌트의 세부 강도 등급은 V1의 3상태를 유지한 뒤 운영 데이터로 조정한다.
- Supabase 보존 주기와 배치 처리 시간은 실제 운영 데이터에 따라 조정하되, UX에서는 오래된 데이터와 미처리 건수를 숨기지 않는다.
- 자동매매·청산은 이 경험의 다음 단계가 아니다. V1의 화면과 카피는 수동 판단과 사후 검증에 머문다.
