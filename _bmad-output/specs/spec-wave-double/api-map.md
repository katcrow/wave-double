# LS OpenAPI 매핑 (docs/api/ls-openapi/)

> Companion: 기능 구현에 필요한 LS OpenAPI TR 매핑. CAP-1~4의 데이터 원천.
> **2026-08-31 갱신** — TR별 InBlock/OutBlock을 원문 대조해 정정했다. 이전 버전은 `t1601`(시장 단위 TR)을 종목별 수급 원천으로 잘못 게재하고 있었다.

## 조건검색 (후보 모집단) — CAP-1

- `t1859` 서버저장조건 조건검색 — 저장한 조건검색식 실행 (주 경로)
- `t1866` 서버저장조건 리스트조회 — 저장 조건 목록
- `t1852` / `t1856` 파일저장종목 (실시간/검색) — 조건검색 세션·터미널 제약 시 **대체 경로(FR-1a)**
  - ⚠️ `t1852`/`t1856`은 `t1859`와 **의미론이 다르다**(파일저장종목 조회 vs 서버저장조건 실행). 반환 모집단이 동일하다는 보장이 없으므로 **원천 구분값(`source`)과 함께 저장**하고, FR-9 집계에서 원천별 분리 조회가 가능해야 한다.

## 종목별 수급·가격 (후보 3일치 행) — CAP-3

**`t1702` 단일 콜로 FR-4의 7개 항목 중 6개가 해결된다.**

- **`t1702` 외인기관종목별동향** — 종목별 기간조회. `foreign-institution.md:30`(InBlock 44 / OutBlock 68)
  - InBlock: `shcode`, `fromdt`, `todt`, `volvalgb`(0:금액 1:수량 2:단가), `msmdgb`(0:순매수 1:매수 2:매도), `gubun`(0:일간 1:누적)
  - **OutBlock1(일자별 배열)**: `date` 일자 · `close` 종가 · `diff` **등락율** · `volume` 누적거래량 · **`tjj0008` 개인** · **`tjj0018` 기관** · **`tjj0016` 외인계(등록+미등록)** · `tjj0007` 기타법인 · `value` 거래대금 외
  - → **종가·등락율·거래량·외인·기관·개인을 한 응답에서 확보.** `fromdt`=2거래일 전, `todt`=당일로 3행을 1콜에 조회.
- **`t1637` 종목별프로그램매매추이** — 프로그램 순매수. `program-trading.md:545`
  - InBlock: `shcode`, `gubun2=1`(일자별)
  - OutBlock1(일자 시계열): `date`, `price`, `diff`, `volume`, `svolume` 순매수수량, `svalue` 순매수금액
  - ⚠️ **`t1636`은 단일 시점 순위형 스냅샷이므로 3일 시계열에 부적합.** 반드시 `t1637`을 쓸 것.
- 대안(참고): `t1716`은 개인·기관·외인 + `pgmvol`(프로그램) + 공매도를 한 응답에 담아 기간조회가 가능해 **단일 TR로 7개 항목 전부**를 커버한다(`foreign-institution.md:250-256`). 다만 기관/외인이 `krx_*`(거래소 기준)이고 PR감산 파라미터(`prapp`/`prgubun`/`orggubun`/`frggubun`)가 값에 영향을 주어 `t1702`와 수치가 달라질 수 있다. 채택 시 두 TR의 값 차이를 먼저 실측할 것.

### ⚠️ 장중 제공 여부 — 2026-08-31 15:22~15:30 KST 실측

| TR | 범위 | 장중 가격·거래량 | 장중 투자자별 수급 |
| --- | --- | --- | --- |
| `t1702` | 종목별 | ✅ 실시간 (`close` 259,000 · `diff` +0.78% · `volume` 13,487,044) | ❌ **전부 0** (`tjj0008`/`tjj0018`/`tjj0016` = 0). 전일 행은 정상 |
| `t1637` | 종목별 | ✅ 실시간 | ❌ `svolume`/`svalue` = 0 |
| `t1601` | 시장 전체 | — | ✅ **실시간** (15:23 기준 개인 +5,733 / 외인 −11,890 / 기관 +517) |

**종목별 투자자별 수급은 장 마감(15:30) 후에야 채워진다.** 따라서:

- 장중 배치는 후보별 **가격·거래량·등락율**과 **시장 전체 수급**만 유효하다. 종목별 수급 힌트(FR-7)는 장중 `판정 불가`가 기본값이다.
- 종가 확정 배치의 cron 시각은 이 값이 채워지는 시각에 맞춰야 한다(PRD §10-1). **투자자별 필드가 전부 0이면 미완료로 처리하고 재시도**하는 가드가 필수다 — 0을 "순매수 0"으로 적재하면 조용히 오염된다.

> ❌ **`t1601`을 종목별 수급에 사용할 수 없다.** `t1601InBlock`의 전체 파라미터는 `gubun1`·`gubun2`·`gubun3`·`gubun4`·`exchgubun` 뿐이며 **종목코드(`shcode`)가 없다**(`investors.md:48-58`). 시장 단위 TR이다.

## 가격/거래량 — 시그널 계산용 장기 일봉 (FR-3a)

- **`t8410` API전용주식차트(일주월년)** (`chart.md:230-242`)
  - InBlock: `shcode`, `gubun=2`(일), **`qrycnt` 최대 500**(비압축), `sdate`~`edate`, `cts_date` 연속조회, **`sujung` 수정주가여부(Y/N)**
  - OutBlock1에 `pricechk` 수정주가반영항목 (`chart.md:289`)
  - → **120거래일 이력이 단일 콜로 해결된다**(`qrycnt=120 ≤ 500`).
- **`t8451` (통합)주식챠트(일주월년) API용** — 동일 구조 + `exchgubun`으로 KRX/NXT/통합 지원. NXT 통합 시세가 필요하면 이쪽.
- ⚠️ **`sujung` 기준 정합 `[검증 필요]`** — 백테스트는 yfinance `auto_adjust=True`(분할 + **배당** 조정)를 쓴다. LS `sujung=Y`가 배당까지 조정하는지 확인해야 하며, 다르면 태깅이 백테스트와 재현되지 않는다(NFR-6).
- 실시간 체결(`S3_`) — 30분 간격 배치 목적엔 불필요.

## 운용 제약 (NFR-3, NFR-7)

**초당 제한 (개인 기준)** — 후보 팬아웃에 쓰이는 TR은 **전부 1건/초**다.

> ⚠️ **NFR-3의 "개인 1~2건/초"에서 상단값 2는 시장 단위 `t1601` 하나뿐이며 팬아웃 구간에 적용되지 않는다.** 예산 산정은 **1건/초** 기준으로 할 것.

> ⚠️ **TR 간 제한 공유 여부는 문서에 명시가 없다.** `README.md:148`은 "초당 전송 건수를 준수"라고만 하고 TR별 독립인지 계정 합산인지 언급하지 않는다. TR마다 값이 다른 구조상 독립 버킷으로 읽히나 **확증 불가** — TR별 토큰버킷 교차 파이프라이닝(종목당 3초 → 약 1초)은 **실측 검증 후에만** 적용할 것.

**실행 시간**: 리포지토리를 **public**으로 운영하므로 GitHub Actions 분은 무제한이다. 제약은 월 사용 분이 아니라 **다음 배치까지의 벽시계 시간(장중 30분)**이며, 처리 규모 상한은 NFR-7(후보 모집단 M ≤ 150)로 관리한다.
