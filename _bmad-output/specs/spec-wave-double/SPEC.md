# wave-double — 매수후보 추천 대시보드 (V1)

## Why

단일 사용자(개인 투자자 Neo)가 백테스트로 확정한 3종 매수 전략(A·B·C)을 매일 조건검색식 후보에 적용해 당일 종가 기준 매수 후보를 자동 추천하는 **1인용 실전운영 도구**이다. 근본은 두 가지다. (1) **고통(pain)**: 우수한 전략을 발굴했지만 이를 매일 종목 발굴로 옮기는 과정이 수동·비체계적이고, 종목별·시장 수급 데이터가 분산돼 있어 한눈에 파악하기 어렵다. (2) **기회(opportunity to capture)**: 검증된 승률(66~69%, PF 1.8~2.1)을 실전 종목 발굴로 자동화한다는 엣지를, 무료·무인 운영으로 오늘부터 확보할 수 있다. 목업 없이 실전운영으로 시작하는 만큼, 백테스트는 104종목 전체 대상인 반면 실전은 **후보 모집단 한정**으로 시그널을 계산하므로 승률 편향이 생길 수 있다 — 이를 `candidate_outcome` 사후 적재로 관찰 가능한 경계 지표로 만들고, 실전 성과가 백테스트 기대치 수준으로 검증되면 그때 자동매매(V2)를 별도 프로젝트로 개발한다.

## Capabilities

- **CAP-1** — 후보 모집단 수집·갱신
  - **intent:** 매 거래일 자동(그리고 수동) 조건검색식(t1859)을 실행하여 후보 모집단을 수집·갱신한다.
  - **success:** 배치가 후보 모집단을 저장하며 누락 없이 완료된다 (실패 시 경고).
- **CAP-2** — 전략 태깅 및 후보 확정
  - **intent:** 후보 모집단 한정으로 전략 A/B/C 시그널을 계산·태깅하고, 태깅된 종목만 대시보드에 노출한다.
  - **success:** 태깅 로직이 백테스트 룰([backtest-baseline.md](backtest-baseline.md))과 일치하며, 태깅(A/B/C, 다중 가능)이 붙은 후보만 목록에 표시된다.
- **CAP-3** — 후보별 3일치 수급 데이터
  - **intent:** 각 후보 종목의 2일전/1일전/당일 3줄(종가·거래량·등락율·외인/기관/개인/프로그램 순매수)을 대시보드에 표시한다.
  - **success:** 후보마다 3행 데이터가 정확히 표시된다.
- **CAP-4** — 시장 전체 수급 화면
  - **intent:** 코스피/코스닥 시장 전체 수급 집계를 화면에 제공한다.
  - **success:** 시장 전체 수급이 대시보드에 표시된다.
- **CAP-5** — 자동·수동 트리거
  - **intent:** GitHub Actions 스케줄로 배치를 자동 실행하고, 시간과 무관하게 프론트엔드에서 수동으로도 트리거한다.
  - **success:** 수동 트리거가 정상 동작하며 배치 이력(`runs`)에 트리거 유형이 기록된다.
- **CAP-6** — 수급 판단 힌트
  - **intent:** 수급 데이터를 단순 노출에 그치지 않고, 후보에 수급 판단 힌트를 표시한다. '좋은 수급'은 **프로그램매수 + 외인 + 기관이 모두 순매수(사고 있는)** 상태로 정의한다.
  - **success:** 이 기준 룰에 따라 후보별로 '좋은 수급'(프로그램+외인+기관 모두 순매수) 여부 힌트가 표시된다.
- **CAP-7** — 실전 사후 성과 추적·검증
  - **intent:** 모든 추천(태깅) 후보의 사후 결과(**TP+3% / SL−3% / TIMEOUT(30거래일 미도달) / 진행중**)를 자동 적재·추적하고, 실전 승률·PF를 백테스트 기대치(A 68.71%/2.05, B 68.95%/2.08, C 66.00%/1.82 — **왕복 0.1% 비용 반영 값**)와 대조하는 검증 화면을 제공한다. 이는 **메인 대시보드와 분리된 '추천후보군 추적페이지'**로 존재한다. (매수 후 복기/검증 목적 — 실제 매도·청산 실행은 아님)
  - **success:** 후보별 `candidate_outcome`이 적재되고, 실전 승률·PF 대 백테스트 기대치 대조 지표가 추천후보군 추적페이지에서 계산·표시된다.

## Constraints

- **전액 무료 운영**: 프론트엔드 Next.js + 로직 파이썬(GitHub Actions) + DB Supabase 무료 플랜만 사용한다.
- **1인용**: 단일 사용자(Neo) 전용 실전운영 도구. 외부 사용자 비타겟.
- **장중 30분 간격 일괄**: 초 단위 실시간 스트리밍 아님. 최종 추천은 당일 종가 기준이며 장중 배치는 추천을 미확정하고 경보·참고 지표로만 동작.
- **데이터 갱신 시점**: 수급·가격의 '당일' 값은 각 스케줄 배치 실행 시점의 최종값을 사용한다(배치시간마다 최종값 보유).
- **백테스트 룰 그대로**: 시그널 당일 종가 진입, 이후 일자별 고가/저가로 TP(+3%)/SL(-3%) 판정.
- **실매매 자동화 제외**: 주문·체결은 Neo가 수동 수행. V1은 추천·추적만.
- **화면 분리**: 메인 대시보드(CAP-1~6: 당일 후보·전략·수급·시장 수급)와 추천후보군 추적페이지(CAP-7: 사후 성과 검증)는 별도 페이지로, 같은 Supabase 데이터를 조회한다.
- **확정 전략 3종만**: A/B/C (정의·파라미터는 [backtest-baseline.md](backtest-baseline.md)) — `docs/보조지표-최적화결과.md` 기준.
- **외부 API·실행 시간 제한 준수**: LS OpenAPI TR별 초당 제한에 맞춰 직렬·스로틀 호출. **후보 팬아웃에 쓰이는 `t1702`·`t1637`·`t8410`은 전부 개인 1건/초**이며 2건/초는 시장 단위 `t1601` 하나뿐이다(api-map.md). **리포지토리를 public으로 운영하므로 GitHub Actions 월 2,000분 한도는 적용되지 않으며**, 실질 제약은 다음 배치까지의 벽시계 시간(장중 30분)과 처리 규모 상한(후보 모집단 M ≤ 150)이다. → PRD NFR-2·NFR-3·NFR-7.

## Non-goals

- **자동매매(주문·체결) 실행** — V1 제외. `candidate_outcome`으로 실전 성과가 백테스트 기대치 수준으로 검증된 뒤 별도 시스템(V2)으로 개발.
- **청산(매도·TP/SL 관리) 실행** — V1은 매수추천까지만. 매도·청산 실행은 이후 별도로 개발(단, 추천 후보의 진입 이후 사후 결과 추적은 CAP-7로 유지).
- **실시간(초 단위) 스트리밍 시세** — 장중 배치는 30분 간격 일괄.
- **금융/투자자문 성격의 조언 기능** — 사실상의 투자 판단 자동 조언.

## Success signal

매 거래일 자동 배치(조건검색 + 태깅 + 수급 + outcome 적재)가 실패 없이 완료되고, Neo가 **메인 대시보드** 하나로 "오늘 후보는 누구, 어떤 전략으로, 수급은 어떤지"를 5분 안에 확인·판단한다. **추천후보군 추적페이지**에서 축적된 `candidate_outcome`으로 **후보 모집단 한정 실전 승률·PF**가 백테스트 기대치(승률 ~68%, PF ~2.0)와 대조 가능하며, 크게 이탈하면 원인(조건검색식 범위, 시그널 재계산 로직)을 점검한다.

## Assumptions

- 전략 A/B/C 시그널은 조건검색식 **후보 모집단 한정**으로 계산·태깅한다(백테스트 104종목 전체 대상과 구분). 승률 편향은 CAP-7의 실전 outcome 적재로 검증.
