## Intent

**Problem:** 5-7의 표본 게이트 view(`candidate_outcome_win_rate_pf_by_strategy_gated`)는 30건 이상이면 승률·PF 수치를 그대로 보여주지만, 그 수치가 백테스트 기대치와 통계적으로 다른지 판정하지 않는다. 표본 30~50건 구간에서는 단일 관측값만으로 기대치 이탈 여부를 판단하기 어렵다.

**Approach:** 5-7 gated view를 소비하는 신규 view `candidate_outcome_win_rate_pf_ci_gated`를 추가해, 게이트 통과 행에 한해 승률의 95% Wilson score 신뢰구간(`ci_lower`/`ci_upper`)을 계산하고, 전략 A/B/C의 고정 백테스트 기대치(68.71%/68.95%/66.00%)가 그 구간 안/밖 어디에 있는지 `expected_in_ci`로 판정해 반환한다. D/E/F 전략과 전체(rollup) 행은 기대치가 정의돼 있지 않으므로 `expected_win_rate`/`expected_in_ci`가 NULL이다.

## Boundaries & Constraints

**Always:**
- `candidate_outcome_win_rate_pf_by_strategy_gated`(5-7)를 그대로 조회해 게이트 판정(`sample_gate_passed`, `total_settled` 등)을 그대로 물려받는다 — 게이트 임계값(30)을 이 view에서 재정의하지 않는다(epic-5-context.md Cross-Story Dependencies).
- `sample_gate_passed = true`인 행에서만 `ci_lower`/`ci_upper`를 계산한다(Wilson score interval, z=1.959963985, round 4자리). 게이트 미통과 행은 NULL.
- 전략 A/B/C에만 고정 기대치를 매핑한다: A=0.6871, B=0.6895, C=0.6600(epics.md Story 5.8). D/E/F와 rollup(strategy IS NULL) 행은 `expected_win_rate`/`expected_in_ci` 모두 NULL — 기대치가 스펙에 정의돼 있지 않은 전략에 대해 값을 창작하지 않는다.
- `expected_in_ci`는 게이트 통과 + 기대치 존재(A/B/C) 조건을 모두 만족할 때만 boolean으로 채운다: `expected_win_rate between ci_lower and ci_upper`.
- 표본이 50건을 초과해도 신뢰구간 판정 로직·우선순위는 동일하게 유지한다(표본 크기별 판정 방식 전환 없음, epics.md AC).

## Design Notes

### view 정의 (`candidate_outcome_win_rate_pf_ci_gated`)

```sql
create or replace view public.candidate_outcome_win_rate_pf_ci_gated as
with base as (
  select * from public.candidate_outcome_win_rate_pf_by_strategy_gated
),
expected as (
  select * from (values
    ('A', 0.6871::numeric),
    ('B', 0.6895::numeric),
    ('C', 0.6600::numeric)
  ) as e(strategy, expected_win_rate)
),
ci as (
  select
    b.*,
    e.expected_win_rate,
    case when b.sample_gate_passed then
      1.959963985 / (1 + (1.959963985^2) / b.total_settled)
    end as z_denom_factor,
    case when b.sample_gate_passed then
      (b.win_rate + (1.959963985^2) / (2 * b.total_settled)) / (1 + (1.959963985^2) / b.total_settled)
    end as center,
    case when b.sample_gate_passed then
      sqrt((b.win_rate * (1 - b.win_rate) + (1.959963985^2) / (4 * b.total_settled)) / b.total_settled)
    end as spread
  from base b
  left join expected e on e.strategy = b.strategy
)
select
  strategy, total_settled, wins, losses, open_count, suspended_count, delisted_count,
  gross_win, gross_loss, win_rate, profit_factor,
  sample_gate_min_required, sample_gate_passed, sample_gate_label,
  round(center - z_denom_factor * spread, 4) as ci_lower,
  round(center + z_denom_factor * spread, 4) as ci_upper,
  expected_win_rate,
  case when sample_gate_passed and expected_win_rate is not null then
    expected_win_rate between round(center - z_denom_factor * spread, 4) and round(center + z_denom_factor * spread, 4)
  end as expected_in_ci
from ci;
```

- Wilson score interval을 쓰는 이유: 표본 30~50건 같은 작은 n, 승률이 0.5에서 먼 값(0.6~0.7대) 모두에서 정규근사(Wald)보다 실제 커버리지가 안정적이다.
- `z=1.959963985`는 `scipy.stats.norm.ppf(0.975)` 값을 SQL 리터럴로 고정한 것 — Python parity 도구도 동일 상수를 써서 4dp까지 정확히 일치시킨다.
- `expected` VALUES는 이 스토리가 유일하게 A/B/C 세 값만 정의한다는 계약을 코드로 강제한다 — D/E/F가 조인에 실패하면 자연히 NULL이 되어 별도 분기 없이 "기대치 없음"이 표현된다.
- revoke는 5-5/5-6/5-7과 동일: `revoke select on table ... from public, anon, authenticated;`.
