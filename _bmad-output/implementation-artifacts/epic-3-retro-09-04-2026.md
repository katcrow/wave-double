## Findings and resolution

### 해결된 수용 차단 항목

1. **운영 migration/function drift** — 최초 회고 시 production에 3.2~3.10 실행 RPC가 없었다. 선행 migration을 포함한 운영 적용 후 `emit_open_command`, `record_outcome_observation`, `price_adjustment_gap_threshold`, `apply_outcome_correction`, `rebuild_outcome_projection` 및 최신 3-인자 `publish_attempt`를 catalog에서 확인했다. 네 개 rollback fixture와 explicit pass row도 통과했다.

2. **local migration 순서와 함수 search_path 재발 방지** — 저장소 순서 검증 스크립트와 CI 게이트를 추가했고, advisor가 보고한 `price_adjustment_gap_threshold()`의 mutable search_path를 forward migration으로 `pg_catalog`에 고정했다. 운영 migration history에는 초기 out-of-order 적용 및 보정 적용 이력이 남아 있으므로, 향후에는 clean reset/parity gate에서 local/production 차이를 자동 차단해야 한다.

### 의도적으로 남긴 후속 항목

3. **GitHub 알림과 자동 DELISTED** — 사용자가 “최대한 나중에 후속으로 처리”하도록 결정했다. 외부 Issue 자동화와 LS 상태 자동 감지는 이번 수용을 차단하지 않도록 별도 open action으로 추적한다. 상태 모델과 수동 correction 경계는 이번 범위에 포함한다.

4. **correction 반복·충돌 및 동시성 fixture** — 데이터 무결성은 보존되지만 반복 correction, unique 충돌의 도메인 오류 정규화, lock protocol을 추가로 명시할 필요가 있다.

5. **데이터 invariant/fixture drift** — `daily_ohlcv.close > 0` invariant와 rebuild fixture 자동 수집은 후속 action으로 남긴다.
