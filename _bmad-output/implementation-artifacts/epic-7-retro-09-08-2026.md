# Epic 7 회고 — 전략 F 통합

## Epic summary

- 회고 기준일: 2026-09-08 (KST)
- 구현 커밋 범위: `b14e3a07c3db2e85d31bc23c309c0b1c2e2e037b..b067e3350badc23ca9c40f7df63debf6b3b8895f` (첫 Story 7.1 커밋의 부모부터 포함)
- 범위 측정: 15개 커밋, merge 0개. 전체 연속 범위에는 전략 G 실험 산출물도 섞여 있어 기능 변경 경로를 별도로 좁혀 리뷰했다.
- 선언된 기준: 코드·스토리 AC·로컬 회귀·마이그레이션 fixture·운영 Supabase 계약·F OOS 문서화

1. `strategy_f.py`가 baseline 지표와 함께 추가됐고, `compute_abc` 및 tagging stage가 A-F를 소비하도록 일반화됐다.
2. F의 TP 3%, SL 4%, cutoff sentinel 999999 규칙과 OPEN snapshot 경로가 forward-only migration으로 작성됐다.
3. F OOS 결과가 문서화됐다. in-sample 77 trades / 승률 75.32% / PF 2.1592에서 holdout 91 trades / 승률 67.03% / PF 1.4382로 하락했지만 유지 결정과 200건 누적 재평가 액션이 기록돼 있다.
4. 로컬 Python·배치·웹 테스트와 TypeScript/build가 통과했고, Playwright MCP에서 `/strategies/F`는 렌더되고 `/strategies/G`는 404 처리됐다.

운영 Supabase 프로젝트 `qqhjeumlecaudsiqhhdu`를 2026-09-08에 MCP로 재조회한 결과 다음이 확인됐다.

- `202609071000_expand_candidate_tags_strategy_check_f`와 `202609080900_parameterize_outcome_strategy_rules_f`가 migration catalog에 없다.
- `candidate_tags_strategy_check`, `candidate_outcome_strategy_check`, `outcome_events_strategy_check`, `outcome_strategy_rules_strategy_check`가 모두 A-E만 허용한다.
- 따라서 Story 7.2의 운영 스키마, Story 7.4의 운영 rule row/constraint, Story 7.5의 운영 OPEN 연동을 현재 운영 환경에서 수용할 수 없다.

Story 문서에는 production fixture pass가 기록돼 있지만, 현재 운영 catalog와 constraint 정의가 그 기록을 재현하지 못한다. 회고 중에는 운영 데이터를 변경하지 않았고, 이 불일치를 해결했다고 간주하지 않았다.

## Findings

### F1. 운영 migration drift가 Epic 7 수용을 차단한다 — blocking

코드와 로컬/fixture 수준의 F 확장은 존재하지만 운영 DB는 여전히 A-E다. 이는 단순 advisor 경고가 아니라 선언된 운영 acceptance와 실제 catalog가 직접 충돌하는 상태다.

- 근거: Supabase MCP `list_migrations`, `execute_sql`의 migration/constraint 조회
- 영향: F tag insert와 F outcome OPEN이 운영에서 CHECK violation 또는 rule 부재로 실패할 수 있다.
- 처분: fix-now. 두 migration을 정확한 순서로 운영에 적용한 뒤, F insert/duplicate/unknown strategy, F rule 값, OPEN snapshot, grants를 명시적 pass/fail fixture로 재검증해야 한다.

### F2. `rebuild_outcome_projection`의 F 회귀 fixture가 없다 — verification gap

`tests/sql/test_outcome_rebuild.sql`에는 F 경로가 없고, `emit_open_command`와 schema fixture만 F를 검증한다. 구현 주석은 rebuild가 전략 비의존적이라고 설명하지만, F payload와 legacy 경계가 실제로 검증되지는 않는다.

- 처분: fix-now. F snapshot payload의 rebuild와 rule 누락/legacy 호환 경계를 SQL fixture에 추가하고 disposable DB와 운영 transaction fixture에서 실행한다.

### F3. F 배지의 실제 소비자 경로가 자동 검증되지 않았다 — verification gap

`strategy-labels` 단위 테스트는 F 라벨을 검증하지만, `StrategyTagList`/실제 카드에 F 태그가 표시되는 경로를 테스트하는 fixture 또는 Playwright 시나리오는 없다. 이번 Playwright 확인에서도 현재 런타임에 F 태그 후보가 없어 배지를 관찰할 수 없었다. 라우트 F/G는 직접 확인했으므로 라우트 수용과 배지 수용을 분리해야 한다.

- 처분: fix-now. 인증된 테스트 데이터 또는 fixture를 사용해 F 태그 카드의 라벨·접힘·링크를 Playwright MCP로 확인하고, G 404도 계속 회귀시킨다.

### F4. Epic 범위에 전략 G 실험 산출물이 혼입됐다 — process/scope risk

정상 Epic 7 커밋 범위 안에 전략 G runner와 대량 CSV 산출물이 포함돼 전체 diff가 100여 파일·11만 줄 이상으로 부풀었다. Story 7.3의 build-auto 기록도 dirty-tree halt를 남겼지만, 이후 이 산출물이 같은 연속 범위에 들어갔다.

- 영향: 리뷰 신호가 희석되고, “첫 스토리부터 마지막 스토리까지” diff의 의미가 Epic 목표와 달라진다.
- 처분: process lesson. 실험은 별도 작업 단위/경로로 격리하고, 스토리 완료 게이트에서 clean tree와 story-scoped diff를 함께 검사한다. 기존 사용자 산출물을 임의 삭제하거나 history rewrite하지 않는다.

### F5. 문서가 주장한 `git diff --check`와 현재 범위가 불일치한다 — low verification/process gap

개별 Story 문서에는 `git diff --check` 통과가 기록돼 있으나, Epic 범위 전체 실행에서는 새 EOF blank line이 `spec-7-3`, `spec-7-6`, `docs/각도가속_이평쌍바닥기법_추가.md`에서 보고됐다.

- 처분: defer/process. 개별 스토리 검사와 최종 Epic 검사 기준을 동일하게 하고, 최종 문서화에는 실제 실행 범위와 결과를 남긴다.

### F6. F OOS runner의 signal/trade 수 차이는 기존 잔여 리스크다 — accepted as-is

OOS 문서에 기록된 `n_signals`와 `n_trades` 불일치(78/77, 95/91)는 전체 baseline(173/168)에도 존재하며 Epic 7에서 runner 코드는 변경하지 않았다. 현재는 새 blocker로 승격하지 않고 기존 Story 7.7의 200건 누적 재평가 액션으로 추적한다.

### 코드 리뷰 triage

`bmad-review`의 adversarial, edge-case-hunter, verification-gap 렌즈를 적용했다. docs-only 변경과 전략 G 실험 산출물은 기능 판정에서 제외하고 Python/API, batch, SQL, web consumer/test 경로만 좁혀 읽었다.

- adversarial: 운영 migration 미적용, 범위 혼입, signal/trade 지표 의미, stale 주석을 확인했다.
- edge-case-hunter: F rule 누락, unknown strategy, duplicate tag, snapshot mismatch는 fixture가 있으나 rebuild F 경계와 실제 카드 소비 경로가 비어 있음을 확인했다.
- verification-gap: 로컬 green 결과가 운영 수용을 대신하지 못하고, SQL rebuild와 F 카드 배지에 실행 가능한 증거가 없음을 확인했다.
