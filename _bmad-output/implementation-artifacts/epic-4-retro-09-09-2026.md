## Assumptions

- 사용자가 “스스로 진행”을 요청했으므로 headless 실행으로 해석했다. Epic은 명시적으로 `epic-4`에서 선택했으며 auto-detect에 의존하지 않았다.
- `detect-epic --epic 4` 결과의 `story_count=10`, `done_stories` 10개, `pending_stories=[]`, retro status `optional`을 완료 게이트의 권위 있는 결과로 사용했다.
- 별도 human confirmation 없이 A1~A5와 B1~B3 remediation을 실행했고 A6는 process lesson으로 구현했다.
- 사용자가 “반려사유를 모두 해결”을 요청했으므로 initial rejection 이후 remediation closure를 같은 문서에 기록했다.
- Team Discussion은 사용자가 요청하지 않아 실행하지 않았다.
- Supabase MCP endpoint가 대상 운영 project와 불일치했으므로 공식 Management API fallback을 사용했다. 로컬 Playwright는 운영 인증을 우회하지 않는 deterministic mock auth/RPC fixture를 사용했다.
