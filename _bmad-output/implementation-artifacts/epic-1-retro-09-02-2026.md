## Findings

### F1 — 루트 TypeScript CI 게이트가 실패한다

- **근거:** `package.json:12`가 CI에 사용하는 `typecheck`를 `tsc --noEmit`으로 정의한다. 루트 `tsconfig.json:3-15`에는 웹 앱이 쓰는 `@/*` paths 및 `allowImportingTsExtensions`가 없고, `apps/web/tsconfig.json:8,29-36`에는 있다. 2026-09-02 로컬 실행 `npm run typecheck`은 alias 미해결 및 `.ts` import 관련 오류로 종료 코드 2를 반환했다.
- **영향:** Epic 1 Story 1.1의 CI 빌드 성공 수용 조건(`_bmad-output/planning-artifacts/epics.md:155-158`)을 충족하지 못한다. 코드 변경이 타입 오류를 포함해도 루트 CI가 녹색이 될 수 없다.
- **처리:** fix now.

### F2 — 운영 Supabase에 후반 스토리 migration이 배포되지 않았다

- **근거:** 로컬 `infra/supabase/migrations/`에는 `202609012200_add_candidate_fallback_support.sql`, `202609012300_add_skip_attempt.sql`, `202609020000_create_dashboard_snapshot.sql`, `202609021000_create_dispatch_outbox.sql`, `202609021100_schedule_dispatch_worker_cron.sql`가 있다. 2026-09-02 Supabase MCP `list_migrations` 결과의 최신 wave-double migration은 `202609012110_revoke_run_rpc_browser_roles`였다.
- **영향:** Story 1.7~1.10의 휴장 skip, dashboard snapshot, 수동 dispatch/outbox/cron 계약이 운영 DB에 존재하지 않아 실제 운영 흐름을 사용할 수 없다.
- **처리:** fix now. 운영 migration 적용 전에는 앱 배포/수동 실행을 완료로 보지 않는다.

### F3 — 운영 `logical_runs`와 `runs`가 RLS 비활성 상태다

- **근거:** 2026-09-02 Supabase MCP `list_tables(public)`는 두 테이블 모두 `rls_enabled: false`이며 critical RLS advisory를 반환했다. 에픽 계약은 브라우저가 approved view/RPC만 읽도록 한다(`_bmad-output/implementation-artifacts/epic-1-context.md:42-43`).
- **영향:** publishable key를 가진 anon/authenticated 역할이 배치 계보 테이블에 직접 접근할 위험이 있으며, approved read-model 경계를 보장하지 못한다.
- **처리:** fix now. 정책을 먼저 설계·검증한 뒤 migration으로 적용한다. RLS를 무정책으로 켜는 변경은 batch/read 경로를 차단할 수 있으므로 이 회고에서 자동 적용하지 않는다.

### F4 — Pretendard 로드가 CSP와 충돌한다

- **근거:** `apps/web/app/layout.tsx:18-21`은 jsDelivr stylesheet를 로드하지만, `apps/web/next.config.ts:57-63`의 `style-src`는 외부 origin을 허용하지 않는다. Playwright MCP로 `http://localhost:3000/login`을 열었을 때 stylesheet가 CSP에 의해 차단됐다는 console error를 관찰했다.
- **영향:** 승인된 Pretendard 기반 UI 계약이 실제 브라우저에서 fallback font로 렌더링된다.
- **처리:** fix now.

### F5 — 선언된 migration 호환성 CI 게이트가 구현되지 않았다

- **근거:** Story 1.1은 clean DB 전체 migration, N/N-1 호환성, generated read-model type diff, SQL fixture 검증을 CI 조건으로 선언한다(`_bmad-output/planning-artifacts/epics.md:160-162`). `.github/workflows/test.yml:69-106`은 Postgres에서 dispatch outbox fixture만 실행하고 cron migration은 제외하며, clean Supabase reset/N-1/type generation 단계는 없다.
- **영향:** 이후 schema 변경이 migration 순서·하위 호환성·읽기 모델 타입을 깨뜨려도 PR CI가 잡지 못한다.
- **처리:** fix now.

### F6 — read-model generated type 계약이 비어 있다

- **근거:** `packages/read-model/src/index.ts:1`은 `export {};`만 포함한다. Story 1.1의 generated DB type 재생성·diff 조건은 `_bmad-output/planning-artifacts/epics.md:160-162`에 명시돼 있다.
- **영향:** 웹의 DB contract drift를 타입 수준에서 조기 탐지할 수 없다.
- **처리:** fix now; F5의 CI 게이트와 함께 구현한다.

### F7 — 인증된 수동 실행의 실제 사용자 경로는 자동 검증되지 않는다

- **근거:** `e2e/manual-trigger.spec.ts:4-12`는 실제 Supabase 로그인, 활성화된 버튼, `/api/dispatch` replay/409 검증을 CI에서 수행하지 않는다고 명시한다. Playwright MCP에서는 미인증 `/`와 `/tracking` 접근이 `/login`으로 리다이렉트되고 로그인 폼 렌더링까지는 확인했다.
- **영향:** 보호 라우트의 부정 경로만 검증되고, Epic 1의 FR2 핵심인 인증 후 수동 실행과 outbox 인계가 깨져도 자동 경보가 없다.
- **처리:** defer. 운영 migration(F2) 완료 후 단일 테스트 운영자 계정 또는 안전한 pre-deploy smoke credential을 사용한 Playwright MCP smoke를 설계한다.

### F8 — CSP regression을 E2E가 감지하지 못한다

- **근거:** `e2e/home.spec.ts:7-16`, `e2e/manual-trigger.spec.ts:15-26`, `e2e/production-smoke.spec.ts:14-37`은 URL·DOM·HTTP status만 확인하며 console CSP error 또는 Pretendard stylesheet의 실제 적용을 검사하지 않는다. F4의 Playwright MCP 관찰에서 regression이 통과 가능함을 확인했다.
- **영향:** UI 자산/CSP 변경이 기능 테스트를 통과한 채 사용자에게만 깨진 모습으로 배포될 수 있다.
- **처리:** defer. smoke에 console error allowlist 또는 실제 font stylesheet response/CSP 계약 검사를 추가한다.

### F9 — 스토리별 commit traceability가 자동화 도구에서 소실됐다

- **근거:** 범위의 27개 커밋을 대상으로 실행한 `git_evidence.py --stories <12 story keys>`의 각 commit `stories` 필드는 빈 배열이었다. sprint status는 하이픈 slug, 커밋은 공백/점 표기를 혼용한다.
- **영향:** 다음 회고·감사에서 스토리별 change volume과 review evidence를 기계적으로 분리할 수 없다.
- **처리:** defer. story completion commit의 subject에 sprint-status key를 그대로 포함하는 규칙을 추가하거나, evidence script의 한글/점 표기 정규화를 보완한다.

### F10 — 스토리 세션 로그가 보존되지 않았다

- **근거:** 저장소 전체 파일 검색에서 story 대화·session transcript가 발견되지 않았고, 구현 산출물은 spec/context/status 문서만 제공한다.
- **영향:** 우회했던 접근, 재발한 실패, 리뷰 수정의 원인을 다음 에픽에서 학습할 수 없다.
- **처리:** accept as-is (이번 에픽). 다음 에픽부터 build/review 결과의 짧은 evidence link를 story artifact에 남긴다.
