## Intent

**Problem:** Story 4.1은 후보별 t1702 가격·외인·기관·개인 값을 저장하지만 프로그램 순매수는 비워 둔다. 이 상태로는 후보 3일 근거 행의 7개 항목과 후속 수급 힌트가 완성되지 않는다.

**Approach:** 기존 supply stage가 후보별 t1702 결과를 만든 직후 LS 공통 클라이언트를 통해 t1637을 후보당 한 번 조회하고, 일자별 `svolume`을 D-2/D-1/D0 행에 trading_day 기준으로 병합해 `program_net`으로 저장한다.

## Boundaries & Constraints

**Always:** t1637 `gubun1=0`(수량), `gubun2=1`(일자별), `svolume`을 사용하고 t1636은 사용하지 않는다. 후보당 t1702 1콜과 t1637 1콜을 순차 호출하며 두 응답 모두 예상 거래일 3개를 충족한 후보만 3행을 저장한다. 한 후보의 API/파싱/날짜 누락은 다른 후보를 막지 않고 partial과 미처리 종목으로 기록한다. 기존 `SupplyRow`/`supply_3day`/stage 상태 계약과 A~F 가변 태그 후보 집합을 유지한다.

**Never:** Story 4.3의 D0 attempt 누적 정책, Story 4.4의 전부 0 재시도·pending/missing 판정, Story 4.5의 시장 수급, UI·힌트 view 또는 새 DB migration을 이번 스토리에 포함하지 않는다. LS 호출을 공통 `LsClient` 밖에서 직접 수행하지 않는다.
