## Goal

Neo가 `/tracking` 페이지에서 추천 후보의 사후 결과(TP/SL/TIMEOUT/OPEN 및 예외 상태)를 확인하고, 실전 승률·PF를 백테스트 기대치와 같은 축에서 대조하며, 백테스트 유니버스(104종목)와 실전 후보 모집단(조건검색식 한정) 사이의 모집단 편향 크기를 직접 관측할 수 있게 한다. 이 화면의 숫자는 V2(자동매매)로 진행할지를 결정하는 유일한 근거이므로, 표본 게이트·동일 비용 모델·컷오프 편향 고지 세 장치가 함께 구현되어야 하며 어느 하나도 개별 후순위화할 수 없다. 세 영역(편향 스키마/계산 → 지표 view → 화면)으로 나뉜 14개 스토리로 5개 에픽 중 가장 크므로, 최소 3개 서브 배치로 나눠 진행할 것을 권장한다.

## Requirements & Constraints

**성과 산식과 분모 규칙**
- 승률 = (손익률 > 0인 종결 건수) / (TP + SL + TIMEOUT 건수), PF = Σ(양의 손익률) / |Σ(음의 손익률)|. 둘 다 왕복 0.1% 비용을 차감한 손익률 기준이며, 백테스트 기대치와 동일한 비용 모델을 쓴다.
- 승패는 종결 상태가 아니라 손익률 부호로 판정한다(TIMEOUT이 양의 손익으로 끝나면 승).
- OPEN은 분모에서 제외하되 항상 별도 카운트로 노출된다. SUSPENDED/DELISTED는 정상 종결 3종과 구분해 별도 처리하고 혼입시키지 않는다.
- `종결 n건 / 진행중 m건`은 게이트 상태와 무관하게 항상 함께 표시한다.

**표본 게이트와 판정 계층**
- 종결 30건 미만이면 승률·PF 수치를 숨기고 "표본 부족(n/30)"을 주 메시지로 표시하며, 기대치와의 대조 판정을 수행하지 않는다.
- 30건 이상에서 전략별 승률의 95% 신뢰구간을 계산하고, 백테스트 기대치(A 68.71%, B 68.95%, C 66.00%)가 구간 안/밖 어디에 있는지 판정한다. 신뢰구간 판정이 모든 표본 크기에서 우선 참조 기준이다.
- 고정 이탈 임계값(승률 ±10%p, PF ±25%)은 신뢰구간 판정을 대체하지 않는 보조 경고로만 병행 표시한다. 표본 크기에 따른 판정 방식 전환은 없다.
- TIMEOUT은 백테스트에 없는 상태이므로 TIMEOUT 건수와 그로 인한 예상 왜곡(N=30 기준 A ±0 / B PF +0.0125 / C ±0)을 함께 표기한다.

**편향 관측 지표**
- 임의 거래일에 대해 "후보 모집단 ∩ 전략 시그널", "백테스트 유니버스 ∩ 전략 시그널", 교집합, 기회 누락 4개 수치가 조회 가능해야 한다.
- 기회 누락에는 후보 모집단 상한(M ≤ 150, 거래대금 상위 결정론적 절단)으로 절단된 종목의 시그널도 포함된다 — 처리 상한이 조용한 누락으로 숨지 않게 하는 것이 이 지표의 목적이다.
- 모든 편향 계산은 비용 절감을 위해 일 1회 종가 확정 배치에서만 수행한다.
- 편향 계산이 유효하려면 유니버스 전체의 시그널 계산이 가능해야 하므로, 후보 모집단에 없는 유니버스 종목의 일봉도 모집단 멤버십과 무관하게 독립 적재/백필해야 한다.
- 미수집과 실제 0을 구분한다: 편향 데이터가 없는 날짜는 0이 아니라 명시적 빈 상태로 표시한다.

**성공 판정 기준**
- 운영 90거래일 시점에 종결 outcome ≥ 50건이 누락 없이 적재되고, 전략별 신뢰구간과 기대치 위치 판정이 표시되어야 한다.
- 임의 거래일에 대해 편향 4개 수치가 조회되어야 한다.
- 게이밍 방벽은 표본 게이트(분모 조작 차단)와 편향 지표(기회 누락 은폐 차단)이며, 경고문이 아니라 이 장치들이 실제 방벽이다.

## Technical Decisions

**지표는 versioned read model에서만 계산한다**
- 승률, PF, 종결/진행중 수, 95% 신뢰구간, 표본 30건 게이트는 versioned SQL view/RPC가 반환하고 UI는 계산하지 않는다.
- 동일 fixture에 대한 Python 기준값과 SQL 결과의 동등성 테스트가 migration gate다 — Python과 화면이 다른 값을 보이는 상황을 원천 차단한다.

**Source별 지표의 유일한 권위**
- 모든 source별 bias/승률/PF view는 canonical published candidate의 `candidate_source_contrib`만 join해 source를 결정한다. outcome 테이블이나 bias 테이블에 독립 source 컬럼이나 JSONB 사본을 두지 않는다.
- 여러 source가 한 candidate에 기여한 경우 primary source는 weight 내림차순 → source 우선순위(t1859 > t1852 > t1856)로 도출한다.

**편향 이벤트 스키마**
- 두 테이블로 분리한다: 회차 메타(`bias_events`, source 컬럼 없음)와 source별 분해 행(`bias_event_by_source`, source × 각 카운트, PK는 회차+source). 이 분해 덕분에 source별 view가 단일 row에서 바로 집계된다.
- append-only: 재계산은 기존 행을 수정하지 않고 새 이벤트로 append하며, canonical view가 동일 거래일에 대해 가장 최근 생성된 이벤트를 선택한다. 과거 이벤트와 그 source별 행은 삭제되지 않는다.

**배치 통합**
- bias stage는 종가 배치 전용이며 premarket/intraday에서는 실행되지 않는다.
- stage 완료는 stage-write RPC로 기록하되, 대시보드 section taxonomy(`candidates`/`tags`/`supply_3day`/`market_supply`/`outcome_tracking`)에 포함되지 않는 독립 옵션 키로 기록한다. 편향 계산 실패가 후보/태깅/outcome 발행을 막지 않아야 한다.
- DB 계약 변경은 forward-only expand-migrate-contract로 진행하고, N/N-1 consumer 호환성을 유지한다.

**계산 재사용 경계**
- 백테스트 유니버스 시그널은 운영과 동일한 공유 전략 계산 진입점으로 계산하며 지표 로직은 변경하지 않는다. 데이터 원천도 실전과 동일한 일봉 테이블을 재사용해 같은 기준으로 비교됨을 문서화한다.
- 유니버스 종목 목록은 백테스트 전용 스크립트에 두지 않고 운영 배치가 직접 import할 수 있는 버전 고정 fixture로 승격하며, 원본과 값이 어긋나지 않음을 테스트로 확인한다.
- 편향 계산은 source별로 독립 분해 수행하며, 비어 있는 source에는 size=0/intersection=0의 null-safe 산식을 적용한다.

## UX & Interaction Patterns

- `/tracking`은 메인 대시보드와 별도 라우트다. 상단에는 메인과 동일한 규칙의 Data trust bar(배치 상태, KST 실행 시각, 트리거 유형, 신선도, 실패 시 수동 실행 버튼)를 두고, `outcome_tracking` section의 run/시각을 기준으로 표시한다.
- Outcome 상태는 배지로 텍스트 표시하며 색상은 보조 수단이다 — 상태 의미는 툴팁이나 상세 문장으로 반드시 제공한다.
- Metric comparison: 전략별(가변 개수) 및 전체를 전환할 수 있고, 실전 값과 기대치를 같은 축에서 비교하며 종결/진행중 건수를 항상 병기한다. 표본 부족 시 부족 메시지가 성과 수치보다 크게 표현된다.
- Bias diagnostic: 날짜 선택 후 숫자 4개와 짧은 설명을 담백하게 보여준다. 차집합을 그래픽 장식으로 과장하지 않고, 편향 차이를 실패 원인으로 단정하지 않으며 참고 정보로 제시한다.
- 검증을 숨기지 않는다: 표본 부족, 모집단 편향, TIMEOUT은 불편하더라도 먼저 노출한다.
- 원천 필터로 승률·PF·편향 지표를 분리 조회할 수 있고, 초기화하면 전체 통합 뷰로 돌아간다. 여러 원천이 혼합된 지표는 혼합임을 화면에서 구분 표기한다.
- 페이지 필터 상태는 뒤로가기/새로고침에도 보존된다. 필터 UI는 키보드로 완전히 조작 가능해야 한다.

## Cross-Story Dependencies

- **에픽 내부 흐름:** 5.1(스키마) → 5.2/5.3(유니버스 시그널·편향 계산) → 5.4(종가 배치 append)가 편향 데이터 파이프라인이고, 5.13/5.14 UI가 이를 소비한다. 5.5(핵심 view) → 5.6(전략·원천 분리) → 5.7(표본 게이트) → 5.8(신뢰구간) → 5.9(보조 임계값)가 지표 계층이며, 5.12가 5.7~5.10을 한 화면에 통합한다. 5.11의 라우트가 5.12~5.14의 컨테이너다.
- **5.8은 5.7의 표본 게이트 판정을 그대로 사용**하며 임계값을 재정의하지 않는다.
- **선행 에픽:** source별 기여 테이블(Epic 1)이 5.1/5.3/5.6의 source 분해 전제이고, stage-write RPC와 Data trust bar(Epic 1)가 5.4/5.11에 재사용된다. 공유 전략 계산 함수와 일봉 적재(Epic 2)가 5.2의 전제이며, `candidate_outcome`과 종결 판정(Epic 3)이 5.5의 입력이다.
- **전략 확장 선행 요구:** 전략 D/E/F를 추가하는 에픽들이 Epic 5보다 **먼저** 완료되어야 한다. 그렇지 않으면 5.6(전략별 분리 view)과 5.12(Metric comparison)가 고정된 전략 수 가정으로 구현된 뒤 재작업이 필요하다. 각 신규 전략의 백테스트 기대치가 코드에서 확인된 값으로 존재해야 대조가 가능하다.
- **부분 실패 격리:** 편향 stage는 필수 발행 조건에서 제외되므로, 5.4의 실패가 다른 에픽의 발행 경로를 막지 않아야 한다.
