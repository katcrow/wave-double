# 후보종목 태깅 조건 (전략 A~I)

> 이 문서는 운영 태깅 파이프라인(`apps/batch/tags_stage.py`,
> `apps/batch/strategy_i_stage.py`)이 후보종목(candidates stage 산출
> 모집단)에 전략 A~I 태그를 붙일 때 사용하는 **현재(Kernel 코드 기준)**
> 조건을 정리한 단일 참조다.
>
> 전략 라벨 텍스트의 출처는 `apps/web/lib/strategy-labels.ts`, 계산 커널은
> `backtest/` 이다. 커널 테스트가 회귀망이므로 본 문서의 조건과 커널 코드가
> 어긋나면 **커널 코드를 근거로 삼는다.**

---

## 1. 태깅 파이프라인 개요

1. candidates stage가 후보 모집단을 산출한다.
2. tags stage(`tags_stage.py`)가 모집단 한정으로 전략 **A~H** 시그널을
   계산한다.
   - 계산 커널: `backtest.strategy_api.compute_abc`
     (`frame`, `ticker=...`, `exclude_terminal_bar=False`)
   - 전략 B·C의 결합 파라미터:
     `backtest/indicator_opt/combine_strategies.py`의 `STOCH_DB`, `DIV3`
   - 전략 A의 합집합·거래량 조합:
     `backtest/indicator_opt/union.py`의 `TOP3`, `VOLUME`
   - 전략 D~H: `backtest/indicator_opt/strategy_{d,e,f,g,h}.py`
3. 전략 **I**는 백테스트 불가(국면 데이터 `t1702` 미보유)이므로 별도 stage
   (`strategy_i_stage.py`)에서 16:00~20:00(KST) 배치 사이클에만 운영 수동
   확인용으로 실행된다.
4. 판정된 태그는 Supabase `candidate_tags` 테이블에 저장된다.

## 2. 공통 전제 조건 (모든 전략 공통)

### 2.1 입력 데이터

- `daily_ohlcv` 테이블의 **수정주가(adjusted=True)** OHLCV. 조회 시
  `trading_day <= cutoff`로 제한해 미래 데이터 유입(look-ahead)을 차단한다
  (`ohlcv_cache_loader.py`).
- DataFrame 컬럼명은 `Open, High, Low, Close, Volume`, 인덱스는 오름차순·
  중복 없는 `DatetimeIndex`.
- 종목별 최소 이력: **`MIN_HISTORY_TRADING_DAYS` = 120 거래일** 미만이면
  `INELIGIBLE_INSUFFICIENT_HISTORY`(이력 부족, 태깅 대상 제외 — 정상 제외이며
  error 아님).

### 2.2 유효 봉(valid OHLCV row) 조건

아래를 모두 만족해야 유효 봉이며, **invalid 행은 계산에서 제외하고 유효
구간만 이어서 시그널을 계산**한다.

- OHLCV 전 값이 유한(finite)
- `Open`/`High`/`Low`/`Close` 모두 양수
- `Volume >= 0`
- `High >= Low`, `High >= Open`, `High >= Close`,
  `Low <= Open`, `Low <= Close`

### 2.3 ATR(14) 필터 (공통 최종 필터)

모든 전략(A~H)의 시그널 봉은 그 봉의 **ATR(14)이 유한하고 0보다 커야** 한다
(`backtest/strategy_api._apply_atr_last_bar_filters`). ATR(기본 14)은 유효
구간별로 계산된다.

### 2.4 "당일 봉이 최종봉" 원칙

- 백테스트 엔진은 각 유효 구간의 **마지막 봉 시그널을 버린다**(이후 청산
  시뮬레이션 봉이 없어서).
- 운영 태깅은 `exclude_terminal_bar=False`로 호출해 **당일 종가로 확정된
  시그널을 당일 바로 잡는다** (Neo 확인, 2026-09-16).
- 태깅 판정: 전략별 시그널 시리즈의 **마지막 봉(`iloc[-1]`)이 True**인 전략만
  해당 종목에 active 태그로 기록된다. 시그널이 없는 경우(전략 전부 미충족)
  해당 종목은 이번 attempt에서 태그가 없다(에러 아님).

### 2.5 조건 판정 방식 (일반)

- 특별한 서술이 없으면 모든 전략 조건은 **당일 봉(마지막 봉) 기준**으로 AND
  조합이다.
- 국소 저점/돌파류 패턴은 모두 **lookahead 없는 forward 순회**로 확정된다.

## 3. 전략별 태깅 조건

### 전략 A — OBV 합집합

라벨: `전략 A · OBV 합집합`. 출처: `backtest/indicator_opt/union.py`
(`TOP3`, `VOLUME`) + `combine_strategies.build_signals`.

```
A = (RSI+CCI와 OBV) ∪ (RSI+IBS와 OBV) ∪ (RSI+ADX와 OBV)
```

- **1위 조합**: `RSI(period=21, threshold=25.0)` &
  `CCI(period=10, threshold=150)` & `OBV(window=3)`
- **2위 조합**: `RSI(period=9, threshold=20.0)` &
  `IBS(threshold=0.3, period=1)` & `OBV(window=3)`
- **3위 조합**: `RSI(period=2, threshold=30.0)` &
  `ADX(length=20, threshold=25.0)` & `OBV(window=3)`
- 각 조합 내 지표 조건은 AND, **3개 조합 결과는 OR**로 합친다.

- **RSI cross**: `RSI(t-1) <= threshold` 그리고 `RSI(t) > threshold`
  (Wilder RSI, `alpha=1/period` EMA 누적).
- **OBV(window=3)**: `OBV > OBV의 3일 이동평균`을 상향 돌파. OBV는
  `sign(Close diff) × Volume` 누적합.
- **CCI(10, 150)**: `CCI(t-1) <= -150` 그리고 `CCI(t) > -150` (침체선 탈출).
- **IBS(0.3, 1)**: `(Close - Low) / (High - Low) <= 0.3` (극단 과매도).
- **ADX(20, 25)**: `+DI가 -DI를 상향 돌파` **그리고 `ADX >= 25`** (DMI,
  `alpha=1/20` EMA).

### 전략 B — 스토캐스틱 쌍바닥 + 주봉 K

라벨: `전략 B · 쌍바닥+주봉K`. 출처: `_signals.sig_stoch_db_weekly_k` +
`STOCH_DB`.

고정 파라미터(`STOCH_DB`):
`k_period=14, d_period=3, threshold=20.0, wk_period=20, wd_period=3`.

```
B = 일봉 slow %K(14-3) 쌍바닥 AND 주봉 slow %K(20-3) 우상향
```

**일봉 쌍바닥**(`sig_stoch_double_bottom`):

- raw %K(14) → 3일 평활(slow %K).
- 쌍바닥 판정(forward, lookahead 없음):
  1. %K 국소 저점이 2개 형성, **둘 다 threshold(20) 이하**(과매도).
  2. 두 저점 사이 반등 고점(넥라인)이 각 저점보다 높다.
  3. 두 번째 저점이 첫 번째 저점보다 **낮지 않다**(높은 저점 / 동일 수준).
  4. %K가 그 **넥라인을 상향 돌파하는 봉 → 시그널**. 돌파 전 두 저점
     아래로 내려가면 쌍바닥 붕괴(취소).

**주봉 필터**(`_weekly_stoch_k`, W-SUN 주 단위 리샘플링):

- 주봉 OHLC(현재 주는 WTD) → raw %K(20) → slow %K(3 평활).
- **당일이 속한 주의 %K > 직전 주 %K**(우상향).

### 전략 C — 3바닥 다이버전스

라벨: `전략 C · 3바닥 다이버전스`. 출처: `_signals.sig_div_stoch3` + `DIV3`.

고정 파라미터(`DIV3`):
`k_period=5, d_period=3, div_window=20, min_gap=5`.

```
C = 가격 3연속 하락/횡보 저점 AND slow %K(5-3) 3연속 상위 저점
    → %K/%D 상향교차
```

- slow %K: raw %K(5) → 3일 평활.
- 가격 국소 저점 3개(연속), `P1 >= P2 >= P3` (하락 또는 횡보).
- %K 저점 3개(연속), `I1 < I2 < I3` (지표는 계속 상위 저점 = 하락
  다이버전스 강화).
- 저점 간격 조건: `i2-i1 >= 5`, `i3-i2 >= 5`, `i3-i1 <= 20`(div_window).
- 확정 봉: %K가 %D를 상향 교차 → 시그널.
- 확정 전에 가격이 셋째 저점(`P3`) 아래로 내려가면 취소.

### 전략 D — 돌파 3%

라벨: `전략 D · 돌파3%`. 출처: `strategy_d.compute_strategy_d`.

고정 파라미터(`STRATEGY_D_PARAMS`):
`breakout_window=20, volume_window=3, volume_ratio_max=0.95, long_sma_window=240,
rsi_period=10, rsi_smooth=6, rsi_threshold=42.0, rsi_min=30.0`.

```
D = 돌파(20봉 신고가) AND 거래량 축적 AND Close<SMA240 AND RSI 상향돌파
```

- **돌파**: `High > max(이전 19봉까지의 신고가, 20봉 rolling)` — 현재 봉
  포함하지 않은 이전 20봉 최고가를 돌파.
- **거래량 축적**: `Volume > 0` **그리고**
  `Volume / max(현재 포함 3봉 최대 거래량) < 0.95`.
- **장기 하락권**: `Close < SMA(240)`.
- **RSI 기세 전환**: RSI(10, Wilder)의 6봉 단순평균이 `전봉 < 42`이고
  `당봉 >= 42`이며 **당봉 RSI >= 30**.

### 전략 E — SMA 골든크로스 + OBV + ADX

라벨: `전략 E · SMA GC+OBV+ADX`. 출처: `strategy_e.compute_strategy_e`.

고정 파라미터(`STRATEGY_E_PARAMS`):
`sma_short_window=20, sma_long_window=60, obv_window=20, adx_window=14,
adx_threshold=20.0`.

```
E = SMA(20/60) 골든크로스 AND OBV 골든크로스(20) AND ADX(14)>=20
```

- **SMA 골든크로스**: `SMA(20) > SMA(60)` **그리고**
  `전일 SMA(20) <= 전일 SMA(60)` (상향 교차).
- **OBV 골든크로스**: `OBV > OBV의 20일 이동평균` **그리고**
  `전일 OBV <= 전일 20일평균` (상향 교차). OBV는 `sign(Close diff) × Volume`
  누적합.
- **추세 확인**: `ADX(14) >= 20`.

### 전략 F — 각도가속 쌍바닥

라벨: `전략 F · 각도가속 쌍바닥`. 출처: `strategy_f.compute_strategy_f`.

고정 파라미터(`STRATEGY_F_PARAMS`):
`slope_window=30, accel_window=5, min_slope_delta=0.004, ma_db_window=16`.

```
F = 로그가격 30봉 OLS기울기 가속 AND MA(16) 쌍바닥(넥라인 돌파)
```

- **기울기 가속**(`sig_angle_accel_ls`):
  - 로그종가 `log(Close)`의 30봉 최소제곱 선형회귀 기울기(slope).
  - `slope >= slope.shift(5) + 0.004` → 5봉 전 대비 기울기가 0.004(일별
    로그수익률 스케일)만큼 가파라짐(가속 ≥ 0).
- **MA16 쌍바닥**(`_double_bottom_signal`, threshold=∞ — 과매도 제약 없음):
  - `SMA(16)` 국소 저점 2개(높은 저점/동일 수준), 두 저점 사이 반등
    고점(넥라인)이 저점들보다 높고,
  - MA16이 넥라인을 **상향 돌파하는 봉 → 시그널**. 돌파 전 두 저점
    아래로 내려가면 취소.

### 전략 G — 양음돌파패턴

라벨: `전략 G · 양음돌파패턴`. 출처: `strategy_g.compute_strategy_g` +
`strategy_custom_vol_breakout_pullback._breakout_pullback_mask`.

고정 파라미터(`STRATEGY_G_PARAMS`):
`min_gain_pct=7.0, vol_sma_window=5, max_pullback=3`, 과열필터 5.0%
(`_MAX_CLOSE_OVEREXTENSION_PCT`, 5거래일 창).

```
G = [5거래일 이내 7%↑ 양봉(거래량↑)]
    → [음봉 1~3회 풀백]
    → [당일 종가가 풀백고가 돌파 + 거래량 전일 대비 증가]
    → [과열 필터]
```

1. **돌파봉**: `(Close-Open)/Open × 100 >= 7%` **그리고**
   `Volume > 전일 기준 5일 거래량 평균`(`vol_sma`는 `shift(1)`).
2. **풀백**: 돌파봉 직후 음봉(`Close < Open`)이 1~3회 연속. 풀백 고가 = 이
   음봉들 중 **최고 High**.
3. **진입 봉**: 풀백 종료(비음봉 도달 또는 3회 상한) 후 **당일
   `Close > 풀백고가`** **그리고** `Volume > 전일 Volume`.
4. **과열 필터**: 당일 `Close <= max(이전 5일 High, shift(1)) × 1.05`
   (5일 고점 대비 5% 초과 상승 제외).

### 전략 H — 240이평돌파

라벨: `전략 H · 240이평돌파`. 출처: `strategy_h.compute_strategy_h`.

고정 파라미터(`STRATEGY_H_PARAMS`): `ma_window=240, slope_ma_window=120`.

```
H = 종가의 SMA240 상향돌파 AND 양봉(Close>Open) AND SMA120 우상향
```

- **240이평 돌파**: `Close > SMA(240)` **그리고** `전일 Close <= 전일
  SMA(240)`.
- **양봉**: `Close > Open`.
- **120이평 우상향**: `SMA(120) > SMA(120).shift(1)`.

### 전략 I — 음봉수급쌍끌이 (운영 수동, 백테스트 불가)

라벨: `전략 I · 음봉수급쌍끌이`. 출처: `apps/batch/strategy_i_stage.py`.

- 실행 시간대: **16:00 이상 ~ 20:00 미만(KST)** — 장 마감(15:30) 후 수급
  데이터 확정 시점부터 매 배치 사이클.
- 판정 조건(모두 AND):

```
I = 오늘 봉이 양봉이 아님(Close <= Open: 음봉 또는 도지)
    AND 외국인 순매수(t1702.tjj0016) > 0
    AND 기관 순매수(t1702.tjj0018) > 0
```

- 시그널일: 마지막 봉의 거래일.
- `params_meta`: `{"batch_kind": "strategy_i",
  "rule": "not_bullish_and_dual_supply"}`

## 4. 태그 저장 및 생명주기

- 저장 테이블: **`candidate_tags`**
  - 컬럼: `tag_id, candidate_id, strategy("A"~"I"), signal_date,
    attempt_run_id, tagged_at, status("active"), params_meta`
  - 업서트 키: `(candidate_id, strategy, attempt_run_id)` — 같은 attempt
    재실행 시 멱등.
  - 하나의 종목이 여러 전략에 걸리면 전략별로 행을 분리 저장한다
    (예: `["A","F"]` → 행 2개).
- **`params_meta`(재현성 스냅샷)**: ATR 14, 전략별 파라미터, `TOP3`/`VOLUME`
  조합, `STOCH_DB`/`DIV3`, `min_history_days`(120)을 `generated_at`과 함께
  기록한다(`tags_stage._build_params_meta`).
- **소멸 태그 동기화**: 태그 upsert 직후 `sync_vanished_tags(p_run_id)` RPC로
  같은 attempt에서 이전에 active였으나 이번에 빠진 태그를 vanished 처리한다
  (story 2.8).
- 실패 구분:
  - `INELIGIBLE_INSUFFICIENT_HISTORY`(120일 미만) → **ineligible**(정상 제외,
    stage success에 포함).
  - OHLCV 로딩 실패 / `SIGNAL_COMPUTE_ERROR` → **error**(stage `partial`,
    `unprocessed_count` 반영).
  - 후보 조회 자체 실패 → stage `failed`(조용한 빈 성공 금지).
